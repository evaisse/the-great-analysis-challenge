# Bend Chess Engine

[Bend 2](https://bend-lang.com/) implementation of the shared `v1` chess engine specification.
Bend 2 is a dependently typed, affine language whose checker also proves that every
definition terminates; it compiles to C (through clang) for native speed.

## Highlights

- Every module passes `ALL PROOFS CHECK`: types, quantities and termination, with no `@unsafe` definition
- Legal move generation with castling, en passant and promotion (including under-promotion)
- FEN import/export, undo, status, repetition and 50-move draw detection
- Minimax with alpha-beta pruning and the deterministic move ordering of `AI_ALGORITHM_SPEC.md`
- `perft 4` = 197281 in ~60 ms (native binary)

## Repository Workflow

Run all validation from the repository root:

```bash
make image DIR=bend
make build DIR=bend
make analyze DIR=bend
make test DIR=bend
make test-chess-engine DIR=bend
```

## Toolchain

Bend 2 is distributed as prebuilt archives only, not through a package manager. The
dedicated toolchain image (`docker-images/toolchain/Dockerfile`) therefore builds it from
its pinned source tag (`v2.0.40`): the compiler is TypeScript run by Bun, and
`bend src/chess.bend -o chess` emits C and compiles it with clang.

## Commands

`new`, `move <from><to>[q|r|b|n]`, `undo`, `ai <1-5>`, `fen <string>`, `export`, `eval`,
`perft <1-6>`, `status`, `hash`, `draws`, `help`, `quit`.

## Layout

| File | Role |
|------|------|
| `src/board.bend` | Packed board (8 × U32, 4 bits per square), position state, FEN, display |
| `src/moves.bend` | Attack detection, pseudo-legal generation, move execution, legality filter |
| `src/pst.bend` | Piece-square tables (generated by `tools/gen_pst.py`) |
| `src/search.bend` | Evaluation, move ordering, perft, alpha-beta |
| `src/game.bend` | Game history, draws, hashing, move parsing, replies |
| `src/chess.bend` | stdin/stdout command loop (entry point) |
| `tests/run.sh` | Scripted CLI tests (`make test`) |

## Implementation Notes

- **Data, not arrays.** The board is eight U32 words, so a position is `Data` and can be copied
  with `+`. Search uses copy-make: no undo bookkeeping, and affinity is never in the way.
- **Matches only inspect parameters.** Bend refuses `match f(x):`, so each decision is a `Bool`
  computed by the caller and passed to a small helper (`gen.p` → `gen.n` → … dispatches on the
  piece type). Cheap choices use the eager `B.sel`.
- **Proven termination.** Board walks count down a `Nat` fuel (`64n`, `8n`); perft and alpha-beta
  are each a single definition recursing on `(depth, move list)`, so mutual recursion is never
  needed; the read loop counts down `4294967295n` commands.
- **Signed scores** are two's complement `U32` values compared with `s.lt` (sign bit flipped).
- **Move ordering** packs `(32767 - score, notation)` into one sortable key that also encodes the
  move, so `List.sort` on `U32` yields score-descending, notation-ascending order.
- `hash` is a 64-bit FNV-1a of the position (two 32-bit lanes), not Zobrist.
